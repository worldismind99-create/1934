# 通勤調整判定ツール（スマホアプリ版）

Google Apps Script 版（`doGet` + HTML 文字列）を、**GASなしで動く単体のWebアプリ**にしたものです。
判定ロジック・学校リスト・画面デザインは元のツールと同じで、ホーム画面に追加して
アプリとして使えるようにしています。

## 元のGAS版との違い

| | GAS版 | このアプリ版 |
|---|---|---|
| 動かす場所 | スプレッドシート／Apps Script のウェブアプリ | 静的ファイルを置くだけ（GitHub Pages など） |
| ホーム画面に追加 | ブラウザのブックマーク扱い | **PWA（アプリとして全画面起動・アイコンあり）** |
| 圏外・機内モード | 開けない | **本体はキャッシュされ、判定はオフラインでも可能** |
| 職場・自宅の入力 | 毎回入力 | **端末に保存され、次回から自動で入る** |
| 用務先の入力 | 毎回手入力 | **よく使う用務先を一覧から選べる（自由入力も可）** |
| Leaflet（地図ライブラリ） | CDNから読み込み | ファイル内に同梱（読み込み失敗なし） |
| 通勤ルート | 地図に線を引くだけ | **距離・所要時間つきのナビ風表示＋Googleマップのナビを直接開ける** |
| 支給区間の距離 | なし | **支給区間の道路距離（片道と合計）を判定結果に表示** |
| 地図が出せないとき | 案内を表示 | 同左（タイルが1枚も取得できない場合も検知して案内） |

判定そのもの（支給区間・通勤調整の文言）は 1 文字も変えていません。

## 通勤ルートの表示

「地図に表示して位置関係を調べる」を押すと、道路に沿った経路を3本ぶん取得して表示します。

| 表示 | 内容 |
|---|---|
| 通勤経路（自宅 ⇔ 職場） | 通勤調整の対象になる区間。地図では青の実線 |
| 自宅 ⇔ 用務先 | 自宅から直行・直帰する場合の経路。オレンジの破線 |
| 職場 ⇔ 用務先 | 職場から出発・帰着する場合の経路。オレンジの点線 |

それぞれに**片道の道路距離と所要時間の目安**が並び、「ナビ」を押すとGoogleマップの
経路案内（音声ナビ）がそのまま開きます。判定結果には、選んだ位置関係に応じた
**支給区間の道路距離**（片道と、その出張での合計）が出ます。

距離はOSRMの計算による参考値です。実際に支給される走行距離は旅行命令に従ってください。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体。Leaflet を含めて **これ1つで完結** します |
| `manifest.webmanifest` | アプリ名・アイコン・全画面表示の設定（PWA） |
| `sw.js` | オフラインで開くためのキャッシュ（Service Worker） |
| `icons/` | ホーム画面用アイコン |

## 使い方

### そのまま試す

`index.html` をダブルクリックして開くだけでも、判定・Googleマップリンクは動きます。
（ホーム画面への追加とオフライン動作には、下記のとおり https で公開する必要があります）

### 公開する（GitHub Pages）

このリポジトリには、アプリ一式をルートに置いた **`gh-pages` ブランチ**を用意してあります。

1. GitHub のリポジトリ → **Settings › Pages**
2. Source を **Deploy from a branch** にする
3. ブランチに **`gh-pages`**、フォルダに **`/ (root)`** を選んで **Save**
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける

この方法は GitHub 側がビルドするため、Actions のトークン権限を必要としません。
アプリを更新したときは、`gh-pages` ブランチにも同じ内容を反映してください。

Actions から公開する経路（`.github/workflows/pages.yml`）も残してありますが、
そちらは **Settings › Actions › General › Workflow permissions** が
`Read and write permissions` である必要があります。

社内サーバーや共有フォルダに置く場合も、この4ファイル（＋`icons/`）をそのまま置くだけです。

### ホーム画面に追加（アプリにする）

- **iPhone / iPad（Safari）**: 共有ボタン → 「ホーム画面に追加」
- **Android（Chrome）**: メニュー → 「アプリをインストール」／「ホーム画面に追加」

追加後はアドレスバーのない全画面で起動し、電波の悪い出張先でも判定部分は動きます。

## 通信について

入力内容はすべて端末の中だけで処理され、どこにも送信されません。
次の場合だけ外部と通信します。

| 機能 | 接続先 |
|---|---|
| 住所から緯度経度を調べる | 国土地理院 住所検索API（`msearch.gsi.go.jp`） |
| 地図の背景 | OpenStreetMap タイル |
| 道路経路の線・距離・所要時間 | OSRM デモサーバー（`router.project-osrm.org`） |
| 「地図：〜」リンク | Googleマップ（リンクを押したときだけ） |

いずれも失敗しても、手動で位置関係を選べば判定（支給区間と文言）は最後まで行えます。
その場合、距離と所要時間は表示されません。
OSRM はデモサーバーのため、業務で常用するなら経路線は無くても支障ありません。

## 一覧を更新するとき

どちらも `index.html` を直接編集します。形式は
`'見出し': [['名称','住所（香川県を除く）'], ...]` で共通です。

| 直すもの | 場所 |
|---|---|
| 学校 | `var SCHOOL_LIST = { ... }` |
| よく使う用務先 | `var DEST_PRESETS = { ... }` |

用務先の初期値は次の2か所です。行を足せば候補が増えます。

| 名称 | 住所 |
|---|---|
| 香川県教育センター | 高松市郷東町587-1 |
| 高松市総合教育センター | 高松市末広町5番地 |

一覧から選ぶと住所が内部で使われるため、地図・距離の精度が上がります。
一覧にないところは、これまでどおり直接入力してください。

## 掲示用のQRコード

`poster/` に、職員に配るためのものを入れています。

| ファイル | 内容 |
|---|---|
| `poster/poster.html` | A4の掲示用。ブラウザで開いて印刷すればそのまま貼れます |
| `poster/qr.png` | QRコードだけ（メールや文書に貼り付ける用） |
| `poster/qr.svg` | 同上のベクター版（拡大しても劣化しません） |

QRの中身は `https://worldismind99-create.github.io/1934/` です。
別の場所で公開する場合は、QRを作り直してください。

## 判定の根拠

香川県「旅費制度の手引き（内国旅行編）」5 旅費の調整 (1)① 通勤手当との調整。
最終判断は各旅行命令権者によります。本ツールは参考用です。
