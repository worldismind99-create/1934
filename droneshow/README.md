# ドローンショー サウンド（観客用スマホアプリ）

ドローンショーの音楽を、会場のどこにいても遅れなく観客自身のスマホで聴くためのWebアプリです。
音は配信せず、事前に端末へ入れた音源を「開演時刻(T0)」ちょうどに各端末が鳴らします。
光は瞬時に届き、音は端末の中で鳴るので、スピーカーからの距離による遅れが生じません。

- 観客用: `index.html`（ホーム画面に追加してアプリとして使えるPWA）
- 運営用: `admin.html`（開演時刻の設定、QR・リンク配布、`show.json`の更新）
- 設定: `show.json`（タイトル、開演時刻、音源URL、シーン一覧）

## 仕組み

| 段階 | 内容 |
|---|---|
| 音源の準備 | `show.json` の `audio` に指定した音源を端末へダウンロードして保持。空ならデモ音源を端末内で合成 |
| 時刻合わせ | サーバーの `Date` ヘッダが次の秒に切り替わる瞬間を短い間隔の HEAD リクエストで捉え、端末時計とのズレを推定（誤差は概ね ±30〜60ms） |
| 開演 | `show.json` または URL の `t0` を絶対時刻として受け取り、Web Audio の時刻指定再生で開始。端末の出力遅延は自動補正、手動補正も可 |
| 開演が押した場合 | 観客ページは20秒ごとに `show.json` を読み直す。運営が `t0` を更新すれば全端末に反映 |
| 画面 | 開演までのカウントダウン、上演中の経過時間と現在のシーン、ビート表示 |

人が映像と音のズレに気づくのは約50ms以上です。会場スピーカーは150m先の観客に約440ms遅れて届くため、この方式の方が同期は良くなります。

## 運営の手順

1. 運行システム(Skybrush等)のショー開始時刻を、`admin.html` に表示されるサーバー時刻に合わせて決める。
2. `admin.html` で開演時刻を入力し、次のどちらかで配る。
   - **リンク・QR**: URLに時刻を埋め込む。テストや小規模向け。時刻を変えたら配り直し。
   - **show.json の更新**: 本番向け。GitHub上で `t0` を書き換えるか、`admin.html` の「GitHubにその場で書き込む」で更新（Fine-grained token が必要）。反映に30秒〜2分。
3. 観客には「会場に着いたら開いて『準備OK』を押し、マナーモードを解除して画面をつけたまま待つ」と案内する。
4. 本番の音源は `bgm.mp3` などをこのフォルダに置き、`show.json` の `audio` にファイル名を書く。

## show.json の項目

```json
{
  "title": "表示タイトル",
  "subtitle": "副題",
  "t0": "2026-10-10T19:30:00+09:00",
  "audio": "bgm.mp3",
  "duration": 120,
  "scenes": [ { "t": 0, "name": "離陸", "color": "#2B3A67" } ]
}
```

`t0` はタイムゾーン付きのISO 8601で書きます。`duration` は音源が無いときの尺(秒)です。
`scenes` の `t` は開演からの秒で、画面のシーン表示に使います（Blenderのフレーム0=離陸開始に対応）。

## 観客ページのURLパラメータ

| パラメータ | 意味 |
|---|---|
| `t0=2026-10-10T19:30:00+09:00` | 開演時刻を上書き（`show.json` より優先） |
| `show=https://…/show.json` | 別の設定ファイルを読む |
| `demo=1` | 音源URLを無視してデモ音源を使う |

## 端末ごとの注意

- **iPhone**: Safariで開く。マナーモードでも鳴るよう無音の音声を先に再生しているが、音量ボタンは上げておく。画面ロックで音が止まるため「画面をつけたまま」にする。ホーム画面に追加すると全画面で使える。
- **Android**: Chrome推奨。画面消灯防止(Wake Lock)が効く。
- **Bluetoothイヤホン**: 機種により100〜250ms遅れる。有線かスピーカーを推奨。使う場合は「同期の状態・微調整」で手動補正。
- 音源をスマホへ配布するには、会場で流す演奏の許諾とは別に複製・配信の許諾が必要です（JASRAC等に確認）。
